## 既知の問題

- **id が改名された場合、解決前の図は汚い。** `db` と `maindb` の両方が残る
  （競合として検出はされる。壊れてはいないが、そのまま貼れる図ではない）
- **pin を持つ要素の削除は、競合が解かれるまで反映されない。**
  消してから聞いても戻せないため、残して聞く設計にした代償
- **重なりの回避は解いていない。** 人が別のノードの真上へ pin を置けば重なる
  （枠からのはみ出しは、枠のほうを広げる形で解決済み）
- 実 AI 役の提案は、このセッションのモデルが書いたもの。
  **API 経由で多数の試行を回したばらつきは測っていない**
- **Git の衝突が 2 件解けていない**（2 人が別々のノードを動かす／別々のノードを足す）。
  形式では解けず、マージドライバが要る。ぶつかった中身自体は人が読める形で出る
- **Mermaid 書き出しの検証は手作業**（mermaid を依存に入れていないため）。
  記録は `experiments/d2/results/mermaid-validation.md`
- `gh repo view` の `visibility` が PRIVATE。CLAUDE.md は public 前提。切り替えは人の判断
- GitHub Issue は 0 件。作業は `.claude/issues/` のローカル Issue で駆動している
- **`oss-privacy-check.sh` が遅い。** 追加行 1 行につき subshell + grep を起こすため、
  未 push の commit が溜まると commit 前のゲートに数分かかる（未 push 13 commit /
  追加 6,990 行で約 5 分）。**検出はしている。速度だけの問題**
