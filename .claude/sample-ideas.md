**思い付きを消さない** —— 消すと、なぜそれを狙ったかが失われる（ベースルール §24）。

## 見るところ

新しいネタを足すときは、**その業界の実物を 1 枚は見てから**書く。
実物を見ないと「箱と矢印」になる。これは 2026-09-12 に間取り図で実際にやった
（オーナーの指摘「不動産の間取り図レベル」）。

見るのは 4 点。

1. **符号**は何か（`C1` / `R-A01` / `OP-10`）
2. **寸法**が要るか。要るなら何を基準に測るか（通り芯・壁芯・区画界）
3. **向きのある線**か、**繋がっているだけの線**か（`arrows`）
4. **その図が無いと何ができないか**（拾い出し・積算・申請・点検）

#### 課題 8 —— 縦横で縮尺を変える

道路の標準横断図を描いて出てきた（2026-09-12）。

全幅 11.5m と舗装厚 250mm を**同じ縮尺**で描くと、舗装が 13px になって
文字が入らない。**実物は H=1/100・V=1/20 のように縦横で縮尺を変えている。**

縦断図（距離 100m 対 高さ 1m）はもっと極端で、**変えないと図にならない。**

いまは `scale: { mm: 20 }` の 1 つだけ。
`scale: { x: 20, y: 5 }` のように分ければ足りるはずだが、
**寸法の数値が縦横で別の縮尺になる**ので、読み手が取り違えないかを確かめる必要がある
（実物は図面のどこかに「H=1/100 V=1/20」と必ず書いてある）。

**逃げ道はある。** 舗装構成だけを別の図に切り出せば、単一の縮尺で描ける（43 がそれ）。
実物もそうしている（横断図に舗装構成の詳細を吹き出しで付ける）。

#### 課題 7 の残り —— まだ描いていない断面・立面

矩計図・橋梁の一般図・縦断図・擁壁の標準断面図・展開図・立面図。
**「○○図」を業界ごとに数えたら、いちばん多くの図がここで止まっていた。**

平面図は「上から見た配置」で、断面・立面は「横から見た高さ」。
**zumen の `kind` は `structure` / `placement` の 2 つしか無く、どちらも上から見ている。**

要るのは新しい形ではなく、**高さの軸**。
`placement` の座標が (x, y) で平面を指すのに対し、断面では y が高さになる。
`kind: section`（断面）を足せば、**同じ道具立てのまま**描ける可能性がある
—— 通り芯は基準線（GL・FL・天端）に、寸法は高さ寸法になる。

**まず確かめること。** 断面図を 1 枚、いまの `placement` で描いてみる。
`y` を高さとして読み替えるだけで足りるなら、足すのは `kind` の語 1 つで済む。

#### 課題 15 —— **正本が「作図の手順」を持てない**（2026-09-15。PdM #6）

見本 127（ロゴのコンストラクション図）を描いて、はっきりした。

「A を中心に半径 AD の円を描く」「その円と AC の交点を D とする」——

|---|---|
| `at: { x: 275, y: 317 }` | `D ＝ 円(C, BC) と 線(A,C) の交点` |
| R を変えたら全部書き直し | **R を 1 か所直すだけ** |
| 何から出た値か読めない | **出どころが式そのもの** |

それは解が一意とは限らず、**ソルバが要る**（過剰拘束・不足拘束・解けないときの扱い）。

**コンパスの筋なら、そこが要らない。** 各手順は前の結果だけから決まるので、
**表計算と同じ前向きの評価**で済む。`intersect`（交点）が付け足しではなく**中心の操作**になる。

##### 人の手直しはどうなるか（**先に決めることが要る**）

ソルバのある図では `pins.position` が意味を失う（位置を決めるのは手順）。
**この製品の芯はそこ（D5・S1）**なので、足すなら
**`pins` は「最初の線分」や「比」に効く**と決めてからになる。

- 実在の要求が 1 件で、**その成果物は既に完成している**（PdM #6 は「急がない」と書いている）

### 家紋の割り出し（見本 129。2026-09-15）

**家紋は、定規と分廻し（竹のコンパス）だけで描かれてきた。**
その作図を、紋章上絵師は「**割り出し**」と呼ぶ。

『標準紋章集成』（1954）にこうある。

> **凡て紋の寸法は九分の紋なれば九分の丸の内で作る**
> **六つ割は一寸の丸を廻せし分廻しにて割る　十二割はこれを更に割る**

| 13 項目 | |
|---|---|
| 1 誰が | 紋章上絵師。京都・東京の組合が技法を継承している |
| 2 何のために | **紋を割り付ける。**寸法を変えても比が崩れない |
| 3 ノード | 基準の丸、割り出しの点、モチーフの円 |
| 4 線・関係 | **半径を円周に回す**（六つ割）。それをさらに割る（十二割） |
| 5 座標 | **無い。**基準の丸の中での比だけ |
| 6 距離 | 比のみ（九分の丸・内円・頭の径） |
| 7 向き | 三つ割は六つ割を 1 つおきに採る |
| 8 色 | 黒 1 色 |
| 9 線種 | 紋は太い実線。**割り出しの跡は薄く残す** |
| 10 業界記号 | 紋そのものが記号 |
| 11 必須ラベル | 紋名（三つ巴・亀甲・木瓜…） |
| 12 手書き | 割り出しの跡 |
| 13 情報密度 | 低い。**円 5〜10 個で足りる** |

**「半径を円周に回すと 6 等分になる」は、分度器を使わずに 60 度を出す作図そのもの。**
`construction`（D36）の `intersect` がそのまま使える —— **新しい語は 1 つも要らなかった。**

**1 つだけ足りなかった** —— **線分を描く手立て**（`segments`）。
「定規とコンパス」の**定規のほう**が無く、六つ割で出した 6 点を結べなかった。

出どころ —— 『標準紋章集成』（1954）／『紋切形』（弘化 5 年）「紋割方の傳」／
『紋割出法』（昭和 46 年・東京紋章上絵師組合）。

**足りているもの** —— 円（`radius` が破線・塗り無しで描く。コンパスの跡そのもの）、
点（`marker: circle` ＋ `tag`）、線（`edges`）、図の名前（`views` の `title`）。
**新しい道具は 1 つも要らなかった。**

**足りていないもの** —— 正本に書いてあるのは**解いたあとの座標**で、
「A を中心に半径 AD の円」という**関係**は書けない。
R を変えると全部を書き直すことになる（PdM #6）。**課題 15 として残す。**

## やり方 —— 図を描いて、足りないものを見つける

**オーナーの指示（2026-09-12）。**

> また既存の図もブラッシュアップするために機能を追加する調査をする
> という **PDCA** を行ってください。

回し方はこう。

1. **実物を見る**（画像検索・設計基準・標準図集）
2. **同じ図を zumen で描く**
3. **並べて、差が出たところを数える**（絵の好みではなく、**何が読めないか**）
4. **足りない道具を 1 つだけ足す**。足したら、既にある図を全部描き直す
5. **毎回、既にあるものを 1 つ以上ブラッシュアップする**（下記）

### 5 の意味 —— 細かい指摘は、まだ来ていない

**オーナーの指示（2026-09-13）。**

> 最初なので、これまで全体を通して細かいことは言っていません。
> PDCA の時に、なにか少しでも改善を入れるみたいな時に
> **徐々にブラッシュアップ**してくれたらと思っています

いま出ていない指摘は、**無いのではなく、まだ言われていないだけ。**
「言われていない ＝ 直さなくてよい」と読むと、粗いところが既定になって固まる。

**1 周につき、新しい図や道具とは別に、既にあるものを最低 1 つ良くする。**
何を直したかは、その周の報告に 1 行で出す（黙って直すと、良くなったことも伝わらない）。

### **描いた図を、必ず 1 枚は実物で見る**（2026-09-15 に足した）

**数の検査は「読めるか」しか見ていない。**

一晩で 26 枚描き、`crossings` / `hiddenLabels` / `crowdedNames` /
`overlappingText` / `straddles` / `hiddenTags` は**全部 0** だった。
それでもブラウザで見たら、こういうものが出てきた。

| 帯（塗り潰し）の上のタブ名が、同じ濃さで沈んでいた | 0 |
| 表の欄から値が飛び出して、行が空に見えた | 0 |
| 箇条書きの行頭が階段状にずれていた | 0 |
| **カメラの視野が、壁を抜けて外まで描かれていた** | 0 |
| 菱形の印の符号が、斜めの辺に食われていた | 0 |

**見たから見つかった。** 数を増やしても、ここは埋まらない。

`pnpm svg <図> out.svg` で書き出してブラウザで開く。
**1 周に 1 枚でいい** —— 見ない周を続けると、崩れたまま積み上がる。

| 東京メトロ 9 路線 | `curve: smooth` だと**川の流れに見える** | 折れ線にした。**実物の路線図は直線で組む** |
| 仕様 §3.0.13 | `color-faint` が「白地に対して」のまま（実装は両方の地） | 仕様を実装に合わせ、実測の表を足した |
| 多層の案内図 | **案内経路が箱の下に隠れた**（`arrows: false` は線を下に敷く） | 1 枚に向きのある線と無い線が混ざる図は、**辺ごとに `ends` で言う** |
| 多層の案内図 | **短い辺で矢印が線より大きく**、逆向きに見えた | 間隔を空けて回避。**矢印の大きさの上限は課題に記録** |
| 多層の案内図 | 階の枠と階名を**手で置いていた**（箱を足すとずれる） | `floors` ＋ `floor` で機械が描く（D26 の ①） |
| 配線略図の信号機 | **塗った丸の外の名前が、白い紙に白い字**で描かれていた | 反転するのは**塗った面の上に載る文字だけ**にした |
| 英語 README | 辿った先の `CONTRIBUTING.md` が**日本語で行き止まり** | 冒頭に英語の要約を置いた |
| 仕様 §3.1 / §3.2 の表 | **`marker` も `curve` も載っていなかった**（実装に追いついていない） | 表を実装に合わせた |
| 編成図 | **2 段に折り返して、連結が逆走して見えた** | 1 列に並べ、向き・パンタ・設備記号を足した |
| ダイヤグラム | すれ違いの交差を、検査が「読みにくい」と言う | **`crossings` は観測値**（合否ではない）。理由を書いた図だけ外す |

**4 の「1 つだけ」を守る。** まとめて足すと、どれが効いたか分からなくなる。

## ずっと先の話（オーナー）

> カメラでぐるーと写真や動画をとると、その内装図がでる

**いまは作らない。** ただし、**出来上がりが `kind: placement` の正本になる**なら、
この製品の形とは繋がる —— 撮って出した図を**人が直せる**ことが、そのまま
この製品の主張（手直しが再生成で壊れない）になるため。

繋がらないのは、**写真から出た図を人が直したあと、撮り直したらどうするか**。
そこが「再生成」にあたる。**S1 と同じ問題**で、そこが解けていない道具は
「一度きりの変換器」にしかならない。

## 業界専用の表示 —— 「できる範囲」で作らない（2026-09-12。オーナーの指摘）

> 路面図と弁当なんですが、**専門的な図面になれてない**と思うんです。
> **今の既存でできる範囲でやっている。** そこはブラッシュアップして、
> **その業界専用の表示**を実現してほしい。

**そのとおりだった。** 図を道具に合わせていた。逆をやる。

| 図 | 「できる範囲」で作っていたもの | 業界の表示 |
|---|---|---|
| 舗装構成断面図 | 層の名前を書いた箱の積み重ね | **材料ごとの模様**（アスコン＝塗り潰し／砕石＝点／路床＝斜線） |
| 弁当の盛付指示書 | 盛付順を隅に小さく | **丸囲みの番号**（実物の指示書の表示） |
| 座席図 | ブロックごとの席数（「前方ブロック 60 席」） | **1 席ずつ丸で描く**（列名 A〜F・席番号 1〜10。実物の座席表と同じ） |
| 工事工程表 | **無かった** | `mark: tick`（時間軸）＋ 負の座標の見出し列 |
| ER 図 | 多重度を「1 対 多」と**文字で** | **鳥の足記法**（`ends`）。DB の人は端の形で読む |
| 電子回路図 | **作れないと言った**（前言を訂正） | `symbol` 13 記号 ＋ 足への自動接続 ＋ 直角配線 |
| UML | **無かった** | `ends` に triangle / diamond / solid-diamond、`line: dashed` |
| 厨房の区域図 | 囲みの名前だけ | **清潔度で塗り分け**（汚染＝格子／準清潔＝斜線／清潔＝無地） |

**これからも、この順で作る。**

1. **実物の表示を先に決める**（記号・模様・符号・寸法の出し方）
2. **足りない道具を足す**
3. できる範囲へ図を寄せない

#### 課題 10 —— 体に巻くもの（**作りかけて捨てた。2026-09-15**）

**足関節のテーピング指示図**を作ろうとして、**2 回作って 2 回とも捨てた。**
記録を残す —— 同じ所で次の周がまた 1 時間使わないために。

**1 回目（箱で描く）。** 下腿と足部を矩形で置き、テープを細い帯の箱にした。
出来上がりは**ただの長方形の積み木**で、トレーナーが見て何の図か分からない。
`専門図面の調査と実装方針.md` §4 が禁じている「boxes ＋ arrows への単純化」そのもの。

**2 回目（輪郭を閉じた曲線で描く）。** これは**半分うまくいった** ——
`via` ＋ `curve: smooth` ＋ `close: true` で、
**下腿と足部の側面の輪郭がちゃんと描けた**（足に見える）。

**捨てた理由は、テープのほう。**
テープは「体に**巻きついた帯**」で、

- 見えている面と、裏へ回って見えない面がある
- 帯には**幅**がある（`weight: thick` は 4px で、帯には見えない）
- 同じ所に何本も重なる（スターアップ 3 本 ＋ ホースシュー 3 本 ＋ たすき掛け 2 本）

太い線を 8 本重ねたら、**輪郭が線の束に埋もれて、何も読めなくなった。**

**分かったこと。**

- **輪郭は描ける。** 面の図（ヤーデージブック＝見本 109）と同じ道具で足が描けた
- **「巻きつく帯」は描けない。** 足りないのは
  **(a) 線に幅を持たせる手段**と、**(b) 裏へ回った部分の表し方**（線を切る）
- 同じ壁は**ロープの結索図**にもある。もやい結び・巻き結びは
  **上を通る／下を通る**が意味そのもので、**下を通る側の線を切って描く**。
  いまの zumen では、辺を分割して手で隙間を空けるしかない

**次に取るなら、先に決めること。** 線に幅を持たせる語（`ribbon` のような）を
足すか、足さずに済ませるか。**D22 に照らすと、値は形の語**でなければならない。
**急がない** —— これが無くても描ける図がまだ大量にある。

#### 課題 11 —— 平行斜線の向き（**いまは足さない。2026-09-15**）

見本 118（特許図面）で出た。特許図面の決まりは

> **切断面には平行斜線。異なる部分は方向を変える**（できないときは間隔を変える）

と言うが、**zumen の `hatch` は 5 種類（none / solid / dots / lines / cross）で、
向きの指定を持っていない。**

**測った。** 見本 118 枚で「隣り合っていて同じ模様」の組を数えると 38 枚で出るが、
**ほとんどは表の見出し（`solid` の帯が並ぶ）**で、これは正しい。
本当に困るのは**見本 104（牛枝肉の分割図）の隣り合う部位**くらいで、
そこも枠線と名前で見分けが付いている。

**いまは足さない。** 足すなら値は形の語でなければならない（D22）——
`lines`（斜め）に対して `bars`（横）・`columns`（縦）なら閉じた語にできる。
**困ってから足す。**
