## コンテナ船の積付図（Bay Plan）の調査（2026-09-14。見本 89）

`.claude/rules/専門図面の調査と実装方針.md` §3 の 13 項目。
英語でも掘った（`bay plan` / `stowage plan` / `slot identification` / `ISO 9711`）。

| | 調べたこと |
|---|---|
| 1 誰が | 本船の一等航海士、ターミナルのプランナー、船社の本船担当 |
| 2 何のため | **積む場所の指示。**あわせて揚げ順・重量配分・復原性の確認 |
| 3 ノード | **スロット（セル）。**1 セル＝コンテナ 1 本。空きスロットも 1 セル |
| 4 線・接続 | **ほとんど無い。**ハッチカバーの線だけ。**線が 1 本も無い図** |
| 5 座標 | **座標そのものが住所。**Bay-Row-Tier（ISO 9711-1）の 6 桁 |
| 6 寸法 | セルの大きさが 20ft／40ft／45ft。ハイキューブは背が高い |
| 7 向き | **船尾から船首を見る。**だから左が左舷、右が右舷 |
| 8 色 | **揚地（POD）ごとの色分け。**実務の標準。色が記法そのもの（D24） |
| 9 線種 | ハッチカバーが太線。ラッシングブリッジも線で入ることがある |
| 10 業界記号 | `R`（リーファー）／IMDG の Class 番号／`OOG` `OH` `OW`（はみ出し） |
| 11 必須ラベル | 総重量（t）・揚地・サイズ／タイプ |
| 12 手書き | 出港間際の差し替え・追加。**紙に赤で書き込む** |
| 13 情報密度 | 1 bay で最大 20 列 × 20 段ほど。実物はもっと詰まっている |

**番号の付け方**（これを外すと図として成立しない）。

- **Bay** … 船首から船尾へ。**40ft は偶数、20ft は奇数**（34 番の両隣が 33・35）
- **Row** … 中心から外へ。**中心が 00、左舷が偶数、右舷が奇数**
- **Tier** … 船倉は 02 から上へ 2 ずつ。**甲板上は 82 から**

**zumen のプリミティブでどう表したか**（道具は足していない）。

| 意味 | 使ったもの |
|---|---|
| 住所 | `at`（**位置がそのまま Bay-Row-Tier**） |
| 揚地 | `palette` ＋ `color` |
| リーファー・危険物 | `tag` |
| 空きスロット | `hatch: none` |
| ハッチカバー | `hatch: lines` の帯 |

**次に作るならこの並び** —— パレット積付図（段数・目地・はみ出し）、
トラック積載図（軸重と前後の配分）、倉庫ロケーション図は既にある（34）。

### ここで見つかった不具合

**`tag` を「路線記号」だと決めてかかっていた。** 積付図の `tag` は
リーファーと危険物の印で、揚地の符号ではない。それでも
`color-without-code` が「tag に符号が無い」と 6 件鳴った。
**見る場所を節から図ぜんたいへ変えた**（同じ周で直した）。

## リンゴ高密植栽培の樹形図の調査（2026-09-14。見本 91）

| | 調べたこと |
|---|---|
| 1 誰が | 果樹農家、普及指導員。**新植のときと、毎年の剪定のとき** |
| 2 何のため | どの高さに何本、どの向きへ枝を置くか。**切る枝を決める** |
| 3 ノード | 主幹・側枝・支柱・ワイヤー・樹の位置（平面図） |
| 4 線・接続 | **枝そのものが線。** 主幹から出る向きと角度が中身 |
| 5 座標 | 高さに意味がある（結果開始高・ワイヤーの段） |
| 6 寸法 | **樹高 3.0〜3.5m／樹間 0.8〜1.0m／列間 3.0〜3.5m。**10a あたり 300〜410 本 |
| 7 向き・角度 | **下垂誘引が記法。** 上向きの枝は伸び続けて実が付かない |
| 8 色 | 使わない（白黒で配る） |
| 9 線種 | 支柱・ワイヤーと枝を描き分ける |
| 10 業界記号 | **切り返し**（枝の途中で切る）と**間引き**（基部から切る）の区別 |
| 11 必須ラベル | 樹高・結果開始高・ワイヤーの段・樹間・列間 |
| 12 手書き | 現地で「この枝を切る」を書き込む |
| 13 情報密度 | 1 本ぶんの側面図 ＋ 数列ぶんの平面図 |

**外してはいけない考え方** —— 高密植は「**密に植えることで小さい樹をつくる**」。
「小さい樹を密に植える」ではない。順序が逆だと、数年で枝が交差して光が入らない。

**側枝の更新** —— 主幹の 1/3 を超えた側枝は**間引いて**更新する。
切り返すと切った先から強い枝が出るので、更新にはならない。

### ここで見つかった課題（道具は足していない）

**線を引くためだけのノードが 15 個要った**（`j0`〜`j4`・`tl*`・`tr*`）。
辺は必ず節と節を結ぶので、**枝のような「ただの線」を引く手段が無い。**

見本ぜんたいで数えると **49 個**（7 枚）。

| 図 | 足場ノード |
|---|---|
| 91 リンゴの樹形図 | 15 |
| 71 列車運行図表 | 12 |
| 83 駅の配線略図 | 9 |
| 73 サビキ仕掛け図 | 6 |
| 61 道路の平面線形図 | 4 |

**正本に「物ではないもの」が混じる**という意味で、これは値段の付く負債。
ただし直し方は 2 通りあり（辺の端に座標を許す／線という別の節を足す）、
**どちらも形式の変更**なので、決める前に案を出す。**この周では足さない。**

## 防虫モニタリングの定点配置図の調査（2026-09-14。見本 92）

| | 調べたこと |
|---|---|
| 1 誰が | 食品工場の品質管理、外部の防虫業者。**毎月** |
| 2 何のため | 虫を殺すためではなく、**どこで何匹捕れたかを月どうしで比べる**ため |
| 3 ノード | 定点（トラップ）と、区画（汚染区・準清浄区・清浄区） |
| 4 線・接続 | 無い。**位置と番号だけの図** |
| 5 座標 | **定点の位置がそのまま意味。** 動かすと比較が切れる |
| 6 寸法 | 区画の広さ。定点の間隔は決めない |
| 7 向き | 侵入の向き（外 → 汚染区 → 準清浄区 → 清浄区） |
| 8 色 | 使わない（白黒で配る。現場に貼る） |
| 9 線種 | 使わない |
| 10 業界記号 | LT（ライト）／ST（粘着）／PT（フェロモン）。**番号は固定** |
| 11 必須ラベル | 定点番号・種類・設置場所・捕獲数・措置値 |
| 12 手書き | 月次の捕獲数と、是正の記録 |
| 13 情報密度 | 定点 10〜30 か所 ＋ 月次の表 |

**外してはいけない考え方。**

- **定点は動かさない。** 番号と位置が固定されているから、増減が言える
- **外の定点には措置値を置かない。** 外に虫が居るのは当たり前で、見るのは中との差
- ライトトラップを**製品ラインの真上に置かない**（捕まえた虫が落ちる）
- ライトトラップを**出入口から見える位置に置かない**（外の虫を呼ぶ）
- 粘着トラップは**壁沿い**（歩行虫は壁に沿って動く）

### ここで見つかった不具合

**22px の印に書いた `tag: LT-1` が、1 つも描かれていなかった。**
図としては「番号の無い丸が 14 個」で、**定点配置図として成立していない。**

落とすこと自体は正しい（伏図の小梁は幅 20px しかない）。
**黙って落とすのが問題**だったので、`hiddenTags` と `tag-hidden` を足した。
入れて回したら、**既にある見本 2 枚でも符号が消えていた**（26・27）。

| 6 寸法 | **保安距離が主役。** 号数ごとに決まっている |
| 7 向き | **風向。** 風下は火の粉が流れる |
| 8 色 | 使わない（白黒で配る） |

| 11 必須ラベル | 号数・保安距離・観覧席の位置・風速の中止条件 |
| 12 手書き | 当日の風向・風速、変更の指示 |

**保安距離（埼玉県煙火消費技術基準 別表 1・第 3 種場所）。**

| 号数 | 玉の直径 | 割物 |
|---|---|---|
| 2.5 号 | 7.5 cm | 40 m 以上 |
| 3 号 | 9 cm | 80 m 以上 |
| 4 号 | 12 cm | 100 m 以上 |
| 5 号 | 15 cm | 120 m 以上 |

| 10 号 | 30 cm | 200 m 以上 |
| 20 号 | 60 cm | 300 m 以上 |
| 30 号 | 90 cm | 600 m 以上 |

数値の大きさで決めると、**同じ図に `45 m` と `5,000` が並ぶ。**

| 2 何のため | どこから塗るか・どの薬をどこに置くか |
| 3 ノード | ブロック（区画）と、スライス |
| 4 線・接続 | 無い。**区画と番号の図** |
| 5 座標 | **書く位置が頭の位置**（歯式・中古車査定図と同じ型） |
| 6 寸法 | スライスの厚み（5〜10 mm） |
| 7 向き | **スライスは横。** 斜めに取ると境目が線になって出る |
| 8 色 | 薬剤の番号で書く（色そのものは塗らない） |
| 9 線種 | 使わない |
| 10 業界記号 | 薬剤（N-6）とオキシの濃度（OX 6% / 3%） |
| 11 必須ラベル | ブロック名・塗る順・薬剤・放置時間 |
| 12 手書き | その人の履歴（前回の薬・既染部の状態） |
| 13 情報密度 | 6 ブロック ＋ 順番の表 |

**外してはいけない考え方 —— 順番が中身。**

- **染まりにくい所から塗る。** ネープ（襟足）は髪が硬く体温が届きにくいので最初
- 顔まわりと頭頂は**体温で早く進む**ので最後
- **全部を同じ仕上がりにするために、塗る時間をずらす**
- **根元（新生毛）と既染部は別の薬。** 既染部に 6% を長く置くと色が抜けて赤くなる

### ここで分かったこと

**新しく入れた `text-overlap` が、自分の間違いを 3 件すぐに捕まえた。**
表の列幅が足りず「フロント（顔まわり）」が外へ出て隣の列に乗っていた ——
**入れる前なら、そのまま見本になっていた。**

## 避難所レイアウトの調査（2026-09-14。見本 95）

| | 調べたこと |
|---|---|
| 1 誰が | 自治体の避難所担当、運営に入る住民、応援の職員 |
| 2 何のため | **開設のとき**に、どこに何を置くかを決める。訓練でも使う |
| 3 ノード | 居住区画・通路・要配慮者スペース・本部・物資・トイレ・発熱者ゾーン |
| 4 線・接続 | 動線（受付 → 一般／発熱者）。**混ぜてはいけない線がある** |
| 5 座標 | 位置に意味（出入口・トイレからの距離） |
| 6 寸法 | **面積と間隔が主役。** 1 人 3.5m² 以上、通路 1〜2m、人と人 2m |
| 7 向き | 出入口の向き。風向（感染症対応の換気） |
| 8 色 | 使わない（白黒で刷って貼る） |
| 9 線種 | 区画の境（テープ表示）とパーティション |
| 10 業界記号 | 無い。**数値そのものが基準** |
| 11 必須ラベル | 区画番号・収容人数・面積・トイレ基数 |
| 12 手書き | 当日の割り当て、世帯名 |
| 13 情報密度 | 区画 20〜60 ＋ 基準の表 |

**外してはいけない考え方。**

- **「入れる人数」ではなく「居られる人数」。** 詰めれば倍入るが、健康被害が出る
- スフィア基準 —— 1 人 **3.5 m² 以上**、トイレ **20 人に 1 基（男女比 1:3）**、
  水 **1 人 1 日 15 L**、蛇口 1 つにつき 250 人まで
- **発熱者と濃厚接触者は、通路も階段も分ける**（受付から直接入れる位置）
- パーティションは**座って口元より高く**（飛沫を止めるため）
- 要配慮者は**出入口とトイレに近い側**。移動が短いほど事故が減る

### ここで分かったこと

**「投影には小さすぎます」が、見本 95 枚のうち 36 枚（38%）で鳴っていた。**
どれも分けようのない図で、**毎回そのまま流していた。**
測り直したら、**その 36 枚は全部 A3 の下限を通っていた** ——
言うべきことは「小さすぎる」ではなく「**印刷して読む図**」だった。

## 防犯カメラの視野図の調査（2026-09-14。見本 97）

| | 調べたこと |
|---|---|
| 1 誰が | 防犯設備士、店舗のオーナー、工事業者 |
| 2 何のため | **どこが写り、どこが写らないか**を決める。見積もりにも使う |
| 3 ノード | カメラ・棚・出入口・レジ・死角 |
| 4 線・接続 | **視野の扇形**（物ではないので破線） |
| 5 座標 | 位置と**向き**が意味。逆光の向きは使えない |
| 6 寸法 | **距離が段階を決める**（DORI） |
| 7 向き・角度 | **画角そのもの。** 広げるほど識別できる距離が縮む |
| 8 色 | 使わない |
| 9 線種 | 視野は破線（実線は物の輪郭） |
| 10 業界記号 | DORI（識別 250 / 認識 125 / 観察 62 / 検知 25 px/m） |
| 11 必須ラベル | カメラ番号・画素・画角・設置高・用途 |
| 12 手書き | 現地での向きの微調整 |
| 13 情報密度 | カメラ 4〜20 台 ＋ 距離の表 |

**外してはいけない考え方 —— 「写っている」と「誰か分かる」は別。**

DORI（IEC/EN 62676-4）は **1m あたり何ピクセルで写るか**で段階を分ける。

| 段階 | 画素密度 | 何が分かるか |
|---|---|---|
| 識別 Identify | 250 px/m | その人が誰かを特定できる |
| 認識 Recognise | 125 px/m | 前に見た人と同じだと言える |
| 観察 Observe | 62 px/m | 服装などの特徴が分かる |
| 検知 Detect | 25 px/m | 人か車かが分かる |

距離は **画素数 ÷（2 × 距離 × tan(画角/2)）** から出る。
4MP・画角 70° なら識別 7.3m、90° にすると 5.1m まで縮む ——
**画角を広げるほど、識別できる距離は短くなる。**

そのほかの決まり。

- **出入口を外向きに撮らない。** 逆光で顔が飛ぶ。内向きに置いて入店者を撮る
- 設置は 2.4〜3.0m。低いと手が届き、高いと顔が上から潰れる
- トイレ・更衣室は撮らない。写り込む隣地や道路はマスクする
- **視野は重ねて置く。** 重なりが無い置き方は、その隙間がそのまま死角になる

### ここで分かったこと

**扇形は、道具を足さずに描けた。**
`from` と `to` を同じ節にして `via` を並べ、`close: true` にする。

ただし **`via` を書かない自分自身への辺は、長さ 0 の線**になり、
節の真ん中に矢印の粒が出るだけだった。**知らせるものが無かった**ので足した
（`edge-self-open`）。あわせて、この書き方を `zumen_spec` の見本にも書いた ——
**書いていない書き方は、エージェントにとって存在しないのと同じ。**

## 円だけで作る動物のマーク（2026-09-15。見本 122。オーナーの発案）

**オーナーの依頼** —— 「円だけで作る、以前のツイッターアイコンみたいな制作図」。
**実在のロゴは商標なので複製しない。** 架空のマークで、**作図の方法**を示す。

**1 回目を捨てた。** 大きい円の足し引きだけで組んだら、
オーナーの言うとおり**ぼんやりした塊**にしかならなかった（「完成品がショボい」）。

**作り直して分かった、動物になるための 3 つ。**

1. **尖った耳は「2 円の交わり（レンズ形）」。**
   円を足していくだけでは、どこまでいっても**丸い塊**にしかならない。
   2 円が重なった部分は**両端が尖る** —— これが耳になる
2. **耳は「先の点」と「根もとの点」で決める。**
   半径と中心で書くと当てられない。先と根もとを置いてから円を逆算する
3. **目と鼻は、塗った輪郭の上に紙色の円で抜く。**
   線で描かない。**抜くほうが小さい円で済み、縮小しても潰れない**

**種類を決めているのは、顔ではなく耳と鼻先。**
顔の円はキツネもネコもイヌもほぼ同じ大きさで、

- **耳を外へ倒して鼻先を伸ばす → キツネ**
- **耳を立てて鼻先を作らない → ネコ**
- **耳を下向きのレンズにして垂らす → イヌ**
- **頭とアゴの 2 円で縦長にし、口もとを大きく抜く → ゴリラ**

円は **4〜7 個**で足りた。

**外してはいけないこと。**

- **輪郭は円と円の「和」と「交わり」だけで決まる。** 直線と自由曲線を使わない
- **尖りは交わりでしか作れない。** 和は必ず丸くなる
- **円を 1 つ動かすと輪郭が全部変わる。** 中心と半径のほうが正本
- **仕上がりだけを渡さない。** 作図の円が無いと、後から直せない
- **円の数は少ないほどよい。** 4〜7 個で足りる

**描いて分かったこと。**

- **できあがる輪郭を、作図の面に太線で重ねると一気に読める。**
  「どの円のどの弧が、輪郭のどこになっているか」が目で追える。
  作図図と仕上がりを**別々に置くだけでは足りなかった**
- **輪郭は、中心から光線を飛ばして拾ってはいけない。**
  最初にそうしたら、**穴（引く円）を跨いだ方向で輪郭が直線に化けた** ——
  領域が星形とは限らない。**marching squares で境界を追う**のが正しい
- **尖った所があるので、輪郭は折れ線（`curve: none`）で描く。**
  滑らかな曲線で結ぶと、円が交わる角で膨らむ。
  作図の円のほうは滑らかな曲線でよい（本物の円なので角が無い）
