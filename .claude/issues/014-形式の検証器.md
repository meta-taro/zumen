# 014 — 形式の検証器（適合を機械で確かめる）

- Phase: 作る順 B1
- 前提: D2 確定済み
- 優先度: 高

## 目的

`spec/zumen-format-v1.md` §8 が適合条件を 5 つ挙げている。
**いまはテストが散らばっているだけで、「この文書は形式に適合しているか」を
1 コマンドで確かめる口が無い。**

口が無いと、第三者の実装が現れたときに適合を確かめる手段が無く、
仕様を分離した意味が半分になる。

## 決めること

- 検証器がどこまで見るか（構造の妥当性だけか、§6 の読み書きの規則まで含むか）
- 壊れた文書を渡されたときに何を返すか（**行番号を含むこと**。
  「不正です」だけでは人が直せない）

## 作業内容

1. 文書 1 つを受け取り、`spec` §3〜§5 に照らして検査する
2. 検査するもの
   - 必須キー（`version` / `nodes`）
   - `id` の一意性
   - `edges` の `from` / `to` が実在するノードを指しているか
   - **`pins` の迷子**（どの要素も指していない鍵）— §3.4 の規則 3
   - 知らないキーを捨てていないか（読んで書き戻して一致するか）— §6.1
3. `pnpm validate <file>` で走る形にする
4. `experiments/` の既存の図と、壊した図の両方で確かめる

## 完了条件

- `pnpm validate` が動く
- **正しい文書を誤って弾かないこと**を、既存の図すべてで確かめてある
- 壊れた文書に対して、行番号つきの指摘が出る
- `spec` §8 の 5 項目のうち、機械で確かめられるものがどれかが文書に書かれている

## 注意

- **迷子の pin を「不正」にしない。** 迷子は競合として人へ出すもので、
  文書として壊れているわけではない（§3.4 の規則 3）。**警告であって失敗ではない**
- 検証器を厳しくしすぎない。**知らないキーを許すのが v1 の規則**（§9）

### 決めたこと — どこまで見るか

**「読めるか」と「人の手直しが行き先を失っていないか」の 2 つだけ。**
仕様 §6 の読み書きの規則のうち、文書 1 つを見て分かるのは §6.1（書き戻し）だけで、
向き・競合・`id` の据え置きは往復させないと分からない。
**分からないものを静的な検査で代用しない**（仕様 §8.1 に書いた）。

| 分類 | code | 重み |
|---|---|---|
| 構文が壊れている | `syntax` | error |
| 最上位が写像でない | `not-mapping` | error |
| `version` が無い／1 でない | `version-missing` / `version-unsupported` | error |
| `nodes` が無い／並びでない | `nodes-missing` / `nodes-not-sequence` | error |
| ノードに `id` が無い／重複 | `node-id-missing` / `node-id-duplicated` | error |
| エッジの端が無い／実在しない | `edge-endpoint-missing` / `edge-endpoint-unknown` | error |
| 読んで書き戻すと行が変わる | `round-trip-changed` | error |
| **迷子の pin** | `pin-orphan` | **warning** |
| 知らない体裁の語 | `appearance-unknown` | warning |
| 実在しない `group` を指している | `node-group-unknown` | warning |

**迷子を error にしない。** error にすると、id が改名された図が CI で落ちるだけになり、
**人が競合として解く経路を潰す**（仕様 §3.4 の規則 3、§6.2）。
終了コードも同じ考えで、**警告だけなら 0** で終わる。

### 完了条件との対応

| 完了条件 | 状態 |
|---|---|
| `pnpm validate` が動く | 済 |
| 正しい文書を誤って弾かないことを、既存の図すべてで確かめてある | 済。**リポジトリの図 13 件すべてが指摘 0 件**。テストは置き場所を走査するので、**図が増えれば自動で対象に入る** |
| 壊れた文書に対して、行番号つきの指摘が出る | 済（重複 id・構文誤りで行を指すことをテストで確認） |
| §8 の 5 項目のうち機械で確かめられるものが文書に書かれている | 済（仕様 §8.1） |

### 注意への対応

- **迷子を「不正」にしていない**（warning、終了コード 0）
- **知らないキーを弾いていない**（`未知のキー` を持つ文書が指摘 0 件で通ることをテスト）

### 残していること

- **`git diff` の読みやすさは見ていない。** これは Issue 011（マージドライバ）の領分
- 検証器は 1 文書ずつ見る。**2 つの版を比べる検査（`id` の据え置き）は持っていない**
