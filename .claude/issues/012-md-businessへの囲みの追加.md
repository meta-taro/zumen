# 012 — ★md-business の本文に図を埋める（着地点）

- Phase: 作る順（B4 だが、D4 により後ろへ置かない）
- 前提: D2 確定済み
- 優先度: **最高**

## 目的

**これがこの製品の着地点である**（D4）。zumen 単体で図を出して終わりではない。

> md-business の Markdown 文書の中に ```` ```zumen ```` の囲みを書くと、
> プレビュー・PDF・HTML 書き出しのどれでも図として出る。

## 受け口は既にある（調査済み）

`md-business/apps/desktop/src/lib/markdown/fencedBlocks.ts` が、本文の囲みを
名前で拾って差し替える汎用の機構を持つ。`mermaid` / `chart` / `data` の 3 つが
同じ口に載っている。

**zumen は新しい仕組みを足すのではなく、この口に名前を 1 つ増やすだけで入る。**

この機構の要点は、差し替えを DOM ではなく**本文の段階で行う**こと
（同ファイル冒頭のコメント）。プレビューも PDF も書き出しも同じ本文を通るため、
「画面には出るのに書き出すと消える」が構造的に起きない。

## 決めること

- zumen 側が md-business へ渡す口の形（関数 1 つか、CLI か、パッケージか）
- md-business 側にどれだけコードを置くか。**薄い接続だけにする**のが望ましい
- 描けなかったときに何を出すか（`loadData.ts` は「黙って空にしない。理由をその位置に出し、
  書いた指定もそのまま残す」としている。**同じ作法に揃える**）

## 作業内容

1. **先に zumen 側だけで、囲みの取り出し → 描画までを通す。**
   md-business を触る前に、こちら側で完結する形を作って試験する
2. md-business の `fencedBlocks` と同じ契約（`collect` / `replace`）に合わせる
3. md-business 側の変更を出す。**別リポジトリなので、変更は PR として出し、
   push・マージは人が行う**
4. 実物の md-business で、プレビュー・PDF・HTML 書き出しの 3 経路すべてに図が出ることを
   人が目で確かめる（検証シート）

## 完了条件

- md-business の文書に ```` ```zumen ```` を書くと図が出る
- **3 経路すべて**（プレビュー / PDF / HTML 書き出し）で出る
- 描けないときに、理由がその位置に出て、書いた指定が残る
- 検証シートの行が起きている（**合否は実物を見た人が記入する。AI が代筆しない**）

## 注意

- **md-business は別リポジトリ。** 勝手に commit・push しない。変更は提案として出す
- md-business は MIT。zumen 側の依存ライセンスを持ち込まないこと（elkjs は
  EPL-2.0 OR GPL-3.0。**Issue 006 の結論が出るまで、md-business へ持ち込まない**）
- md-business の作法（差し替えは本文の段階で・黙って空にしない）に合わせる。
  こちらの都合で別の作法を持ち込まない
