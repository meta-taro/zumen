# 007 — 出した図が、貼り先で崩れないか

- Phase: 作る順 B2
- 前提: Issue 004
- 優先度: 中

## 目的

構成図は**単体で見るものではなく、資料に貼るもの**である。
出力が資料側で崩れると、人はそこで手作業に戻る（そして図はまた腐る）。

原案 §26 の 7 が同じことを言っている。

## 作業内容

1. 出力を、実際に使われる貼り先で開く（プレゼン資料 / 文書 / Markdown / ブラウザ）
2. 崩れる条件を列挙する（フォント・線・グラデーション・テキストの位置）
3. 崩れないための出力設定を決める

## 完了条件

- 貼り先ごとの結果が書かれている
- 崩れる条件と、その回避方法が書かれている
- **回避できないものは「できない」と書かれている**（できるように読める書き方をしない）

### 貼る前に見つかった問題 3 つ（直した）

| 見つかったもの | 何が起きるか |
|---|---|
| **`font-family` が 1 つも無かった** | 書体を貼り先の既定に委ねることになり、**日本語のラベルが豆腐（□）になり得る** |
| `orient="auto-start-reverse"` | **SVG 2 の値。** 古い解釈系では矢印の向きが決まらない。`marker-end` しか使わないので `auto` で等価 |
| `width="490.66666666666663"` | 貼り先へ渡す寸法が不安定。**Markdown 埋め込みの data URI も膨らむ** |

書体は**総称ファミリ（`sans-serif`）だけ**にした。
具体的な書体名は書かない — **見た目は人が決める領域**（ベースルール §11）。
`DESIGN.md` が決まったら `src/render.ts` の `FONT` 1 か所を差し替える。

### 使わないと決めた機能を、テストで固定した

`<style>` / `foreignObject` / グラデーション / フィルタ / **`dominant-baseline`** /
`xlink:` / `<image>` / `auto-start-reverse`。

**文書に書くだけだと、半年後に誰かが足して終わる。**

### 回避できないもの（**できないと書いた**）

- **書体の実物は貼り先が決める。** SVG に書けるのは名前だけ。
  機械が変われば文字の幅が変わり、**長いラベルは箱からはみ出す**。
  回避には「書体の埋め込み（数百 KB〜数 MB ＋ライセンス）」か
  「文字を図形に変換（選べない・検索できない・差分が読めない）」が要る。
  **どちらも採っていない。** 実際にはみ出してから人が決めること
- **SVG を受け付けない貼り先には、SVG 側では何もできない。**
  PNG 化にはラスタライザが要るが、依存を増やすので**要ると分かってから入れる**
