- Phase: 作る順（急がない）

## 目的

原案 §29 は draw.io を「将来的な Import/Export 先および UX 参考対象」としている。
D2 では **draw.io XML を正本にしない**と決めたが、**書き出し先としては別の話**である。

Mermaid 書き出しは「翌日**読める**」を担保する。
draw.io 書き出しは「翌日**編集できる**」を担保する。ここが違う。

## 決めること

- 位置・大きさ・線の曲げ方をどこまで写すか（draw.io は全要素が座標を持つので、
  **人の指定と自動配置の区別は写せない**。この情報が落ちることを明記する）
- 圧縮するか（draw.io は既定で deflate+base64 する。**しない**。差分が読めなくなる）

### 決めたこと（このリポで決めてよい、とされていた 2 点）

**1. 位置・大きさ・線の曲げ方をどこまで写すか**

**全部写す。ただし「人の指定か自動配置か」の区別は形式に無い。**
draw.io は全要素が座標を持つため、区別を置く場所が無い。

そこで人が置いた要素だけ `<object ... zumenPinned="1">` で包んだ。
draw.io の「データを編集」で見えるので、**開いた人が誰の指定かを確かめられる。**
ただし **draw.io で保存し直すと失われることがある**ので、それも断り書きに書いた。

**2. 圧縮するか**

**しない。** draw.io は既定で deflate + base64 するが、
それをすると `git diff` が読めなくなり、テキスト正本にした意味が消える。
draw.io は非圧縮の XML もそのまま開く。

### 落ちるもの（先頭のコメントに列挙してある）

- 人が置いた位置と自動配置の**区別**
- `appearance` の意味の語（`primary` / `muted`）— 色に変換されるので語は残らない
- 正本のコメントと並び順
- 競合を解いたときの記録（`locked`）
- **往復できないこと**（正本は `.zumen.yaml` の側）
