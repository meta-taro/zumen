# 005 — 承認のための最小 GUI の範囲を決める（編集機能一式を作らない）

- Phase: 作る順 B3
- 前提: Issue 001 が Go / Conditional
- 優先度: 中

## 目的

**このプロジェクトが最も失敗しやすいのがここ。**

原案 §7 の v0 必須操作（選択・ドラッグ・リサイズ・接続・テキスト編集・削除・Undo・
Zoom / Pan・保存）は、**既存の作図ソフトの機能一覧と区別がつかない**。
これを揃えることを目標にすると、機能の少ない作図ソフトが出来上がり、
draw.io を採らなかった判断（D1）を自分で裏切ることになる。

GUI に要るのは編集機能そのものではなく、**AI の書き換えを人が承認できること**である。

- AI が何を書き換えたのかが見えること
- 人が動かしたものを AI が戻していないかが見えること
- 戻されていたら、そこだけ人の指定として固定できること

## 決めること（このリポで決めてよい）

- 上の 3 つを成立させるのに必要な操作は何か。**そこから逆算して機能を決める**
- 逆に、v0 で**やらない**操作を明記する

## 完了条件

- v0 の操作一覧が、**「承認のためにこれが要る」という理由付きで**書かれている
- やらない操作が列挙されている
- **見た目の完成度を完了条件にしていない**（汚くてよい）

## 注意

- **使いやすさの改善に時間を吸わせない。**ここが最大の失敗経路
- 機能を足したくなったら、Issue 003 の指標が改善するかで判断する。
  改善しない機能は、この製品の機能ではない

### 2026-09-06（同日・追記）— **実際に動かしたら、丸ごと動いていなかった**

「ビルドが通る」で報告したのは誤りだった。人から
**「立てるのはあなたができること。人が本当にやらないといけないことか確認して」**
と指摘され、自分で dev サーバと headless Chrome を立てて動かした。結果、

| 見つかったもの | 何が起きていたか |
|---|---|
| **`src/messages.ts` の `resolveLocale` が既定引数で `process.env` を触っていた** | ブラウザに `process` は無い。**文言を 1 つ使った瞬間（`validate`）に全体が止まり、図が 1 つも描かれていなかった** |
| 線と矢印が `--border-strong`（ヘアライン用の薄さ） | **地に沈んで読めない。**「図の主役は関係」と自分で書きながら、その関係を見えなくしていた。`--text-secondary` へ |
| テーマに追随していなかった | `data-theme` を誰も設定せず `prefers-color-scheme` も見ていない。**人の Chrome では強制ダークで潰れていた**。`light-dark()` で 1 行にまとめた |

**ビルドが通ることと動くことは別。** そして**それを確かめるのは AI の仕事**で、
人に頼むところではなかった。

### 確認をコマンドにした — `pnpm gui:check`

同じ見落としを繰り返さないため、**8 操作の通し確認を自動化した**（`scripts/gui-check.mjs`）。
dev サーバと headless Chrome を自分で立て、CDP で操作して 21 項目を見る。
Chrome が無い環境では**「確認できなかった」と言って終わる**（黙って通さない）。

守っている項目のうち、この製品の中心は 2 つ。

- **人の位置指定が、提案の差分に出ない**
- **提案を入れても、人の指定が消えない**
