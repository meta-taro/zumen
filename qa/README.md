# 検証（git-qa）

zumen のデスクトップアプリを、**人が見て署名する**ための場所。

`pnpm gui:check` とは役割が違う。

| | 何を見るか | 誰が判定するか |
|---|---|---|
| `pnpm gui:check` | 8 つの操作が**動くか**（39 件） | **AI**（無人で緑になる） |
| ここ（git-qa） | **人が見てどうだったか** | **人だけ** |

`gui:check` が緑でも、**誰もアプリを見ていない状態**はあり得る。
`product-baseline.md` §29 がそこを名指ししている。

> commit・テスト通過・Issue クローズ・デプロイ成功は、**AI が無人で発生させられる。**
> 活動量を見ている限り、人が関与していないことは検出できない。

## 中身

| | |
|---|---|
| `git-qa.json` | ここが git-qa のワークスペースであることの印 |
| `デスクトップ-検証シート.tsv` | 見る項目（10 件）。**手順と期待結果は git-qa が読める書き方で書く** |
| `runs/<日時>/` | 実行 1 回分の証跡（`run.json` と画面）。**git-qa が作る。手で書かない** |

## 走らせる（人）

git-qa を持ってきて、このフォルダをワークスペースとして開く。

```bash
pnpm app          # zumen のデスクトップアプリを立ち上げておく
# 別の端末で git-qa を起動し、ワークスペースに zumen の qa/ を指定する
```

証跡は `qa/runs/<日時>/` に増える。

## 読み返す（誰でも）

```bash
pnpm qa:verify
```

いちばん新しい証跡を読み返して、**通してはいけないものを止める。**

| 見るもの | どうなるか |
|---|---|
| 証跡がまだ無い | **終了コード 2。**走らせていないことを「通った」と書かない |
| `FAIL` がある | 止める |
| `VERIFIED` が 0 件 | 止める。**`AUTO_PASS` は「誰も見ていない」であって合格ではない** |
| シートが判定のときから変わった・消えた・記録が壊れている | 止める |
| 相手が走行中に入れ替わった | 止める |
| 途中で止まった実行 | 止める |
| `AUTO_PASS` / `SKIP` / `BLOCKED` がある | 止めない。**件数は必ず出す** |

**`pnpm test` には入れていない。**
人が走らせるまで落ち続ける関門なので、常時緑であるべき検査と混ぜると、
どちらかを黙らせることになる。読み返す側の中身は `test/qa-verify.test.ts` で見ている。

## 書き方（シート）

git-qa が読める形は決まっている。**この形から外れた行は、人が手で操作する行になる。**

| | 書き方 |
|---|---|
| 手順 | `アプリを起動する` / `「X」をクリックする` / `「X」を押す` / `「A」に「B」と入力する` |
| 期待結果 | `「X」と表示される`（**鉤括弧が 1 組のときだけ**） |

複数の手順は、同じセルの中で改行して並べる。

## やってはいけないこと

- **AI が `VERIFIED` を置かない。** git-qa の MCP に判定を置く道具は無い。**回り道を探さない**
- `runs/` を手で書かない。書いた時点で証跡ではなくなる
- 落ちた項目を消して通ったことにしない
