# 図形とアイコンのライセンス — 調査結果と決定（Issue 006）

- 調査日: 2026-09-04
- 対象: 原案 §8「Cloud」が挙げる提供元（AWS / Microsoft Azure / Google Cloud /
  Cloudflare / Docker / Kubernetes）の公式アイコン
- **これは法的助言ではない。** 配布の前に、最終確認は人が行うこと

---

## 1. 決めたこと

**クラウド各社の公式アイコンは、1 つもリポジトリに同梱しない。**

zumen が同梱するのは、**自分で描いた汎用図形だけ**（原案 §8 の
Internet / Cloud / Client / User / API / Queue / Cache / Container / Cluster / Network）。
これらは zumen の著作物で、リポジトリと同じ MIT で配布する。

公式アイコンを使いたい利用者は、**自分で提供元から取得して自分の環境へ置く**（§4）。

---

## 2. 根拠 — 提供元ごとの条件

「同梱」は **zumen のリポジトリ／配布物にアイコンのファイルを入れて再配布すること**を指す。
「図に使う」こととは別の話であり、各社が許しているのは主に後者である。

| 提供元 | 同梱してよいか | 改変してよいか | 表示義務 | 出典 |
|---|---|---|---|---|
| **AWS** | **不可**（許諾の対象が「顧客・パートナー」に限られ、第三者ツールへの同梱は範囲外） | **不可** | 定型文あり（再販者向け） | [AWS Trademark Guidelines](https://aws.amazon.com/trademark-guidelines/) / [AWS Architecture Icons](https://aws.amazon.com/architecture/icons/) |
| **Microsoft Azure** | **不可**（許諾は「図・研修資料・文書」での使用に限定。ツールの素材として配ることは含まれない） | **不可** | 図中にサービス名を併記することを推奨 | [Azure Icons](https://learn.microsoft.com/en-us/azure/architecture/icons/) |
| **Google Cloud** | **不可**（Google Brand Features の改変禁止。ロゴは承認済みの版のみ） | **不可** | 記載あり（登録国以外で ® を使わない等） | [Google Trademark Guidelines](https://partnermarketinghub.withgoogle.com/brands/google/trademarks-and-terms/trademark-guidelines-for-proper-usage/) |
| **Cloudflare** | **不可**（ロゴ使用は原則として書面の許可が要る） | **不可** | 定型の帰属文を初出ページ下部に置く | [Cloudflare Trademark](https://www.cloudflare.com/trademark/) |
| **Docker** | **不可**（ロゴは Docker の許可を得たうえで公式素材から取る） | **不可** | 「Docker and the Docker logo are trademarks or registered trademarks of Docker, Inc.」 | [Docker Trademark Guidelines](https://www.docker.com/legal/trademark-guidelines/) |
| **Kubernetes / CNCF** | **不可**（Linux Foundation の商標方針。製品・サービスの宣伝素材への使用は書面の許可が要る） | **不可**（色変更・重ね合わせ・拡縮の改変を禁止） | 後援・推奨を示唆しないこと | [cncf/artwork](https://github.com/cncf/artwork) → [LF Trademark Usage](https://www.linuxfoundation.org/legal/trademark-usage) |

### 引用（一次情報の原文）

**Microsoft Azure** — 「Icon terms」節。

> Microsoft permits the use of these icons in architectural diagrams, training materials,
> or documentation. You can copy, distribute, and display the icons only for the permitted
> use unless granted explicit permission by Microsoft. Microsoft reserves all other rights.

同ページ「Don'ts」:

> Don't crop, flip, or rotate icons. / Don't distort or change icon shape in any way. /
> Don't use Microsoft product icons to represent your product or service.

**AWS** — Architecture Icons ページ。許諾の相手が限定されている。

> We allow customers and partners to use these toolkits and assets to create
> architecture diagrams.

同じく Trademark Guidelines。

> You will not alter the logo images in any manner, including but not limited to changing
> the proportion, color, or font of the AWS Marks, or adding or removing any elements to
> or from the images.

**Docker** — Trademark Guidelines。

> The design elements may only appear with the words, logotype, graphic elements and
> spacing which Docker has previously approved for use and may not be modified,
> recombined or displayed in modified scenes, images or other artwork.

**Cloudflare** — Trademark policy。

> You may not modify Cloudflare trademarks, abbreviate them, or combine them with any
> other symbols, words, or images, or incorporate them into a tagline or slogan.

**Google** — Trademark guidelines。

> Don't remove, distort, or alter any element of a Google Brand Feature.

**Linux Foundation**（Kubernetes を含む CNCF プロジェクトのロゴ）—

> Do not use a logo of The Linux Foundation on posters, brochures, signs, websites, or
> other marketing materials to promote your events, products or services without written
> permission from The Linux Foundation.

### 確認できなかったこと（断定しない）

- **Google Cloud の icon library（https://cloud.google.com/icons）の利用条件の原文は取れていない。**
  ページ本文が JavaScript で描画されており、HTML には footer しか含まれない。
  取得を 3 回試みて、いずれも terms に相当する文を得られなかった。
  上表の Google の行は、**icon library ページではなく Google の商標ガイドライン**を根拠にしている。
  同梱しないという結論はこれで足りるが、**「Google Cloud のアイコンは同梱してよい」と言うには
  この原文が要る。**
- 各社とも「第三者の作図ツールにアイコンを同梱してよい」と**明示的に許可した文は無い。**
  無いことを「禁止」と読むのは厳しすぎるが、**public リポジトリに入れると履歴に残る**以上、
  ここは厳しい側に倒す。

## 3. 同梱するもの — 自作の汎用図形

原案 §8「Generic」の図形は、**zumen が自分で描く。**

- Internet / Cloud / Client / User / API / Queue / Cache / Container / Cluster / Network
- 各社のアイコンを**なぞらない・簡略化して真似ない。**
  形が似ることを避けるのではなく、**元データを参照しないで描く**という手順のこと
- ライセンスは MIT（リポジトリ本体と同じ）。`LICENSES.md` に書く

**現状、実装にはまだ図形の種別による描き分けが無い。**
`spec/zumen-format-v1.md` §3.1 の `nodes[].type` が接続点であり、
未知の `type` は `generic` として描くと既に決めてある。

## 4. 同梱しないものの入れ方（アイコンパック）

**提供元から利用者が自分で取得し、自分の環境へ置く。**
zumen はファイルを配らず、**置き場所と読み方だけを決める。**

### 置き場所

```
<プロジェクト>/.zumen/icons/<パック名>/<アイコン名>.svg
```

`.zumen/icons/` は **`.gitignore` に入れることを既定として案内する。**
利用者のリポジトリが public だった場合に、同じ問題を利用者側で起こさせないため。

### 対応づけ

パックごとに 1 枚の対応表を置く。`nodes[].type` から SVG のファイル名を引く。

```yaml
# .zumen/icons/aws/pack.yaml
name: aws
source: https://aws.amazon.com/architecture/icons/
notice: |
  Amazon Web Services, AWS, and the Powered by AWS logo are trademarks of
  Amazon.com, Inc. or its affiliates.
map:
  server: Arch_Amazon-EC2_48.svg
  database: Arch_Amazon-RDS_48.svg
```

- `source` と `notice` は **利用者が書く。zumen が既定値を持たない**
  （持った時点で、zumen が条件を代弁したことになる）
- パックが無い `type` は `generic` として描く。**壊れない**

### 表示義務への対応

`notice` に文字列があれば、**書き出した図に添える。**
入っていないものを zumen が補わない。

### 改変の禁止に対応するために

読み込んだ SVG は**そのまま貼る。** 色の差し替え・比率の変更・切り抜きをしない。
`appearance`（仕様 §4）で色を指定されても、**アイコンには適用しない。**

---

## 5. これを止めるべき条件

- **提供元が第三者ツールへの同梱を明示的に許可していると分かった場合。**
  そのときは、その提供元だけを同梱の側へ動かす（全部まとめて動かさない）
- アイコンパックを利用者に用意させる手間が重すぎて誰も使わないと分かった場合。
  ただし**逃げ道は「同梱する」ではなく、取得の手順を減らすこと**
- draw.io 書き出し（Issue 013）で、**向こう側のアイコン名を書くだけで済む**と分かった場合。
  ファイルを持たずに図が成立するなら、この節ごと不要になる
