# 作図（`kind: construction`）の骨格

- 決定: **D36**（`.claude/decisions.md`）
- 発端: PdM #6「正本に座標を書かずに図を作れるようにしたい（円と比だけの作図）」
- 実装: **まだ無い。** この文書は骨格で、通ってから実装する

---

## 1. 何を解く話か

いまの `placement` は**座標を書かせている。**

```yaml
- id: d
  at: { x: 275, y: 317 }     # この 275 がどこから出たのかは、正本に書いていない
```

`appearance` では「**正本には色を書かない。語だけを書き、色は描き手が決める**」と決めてある
（仕様 §4）。**位置についても同じことが言える。**

> **正本には座標を書かない。関係を書き、座標は描き手が解く。**

### 実測 —— どれくらい困っているか

| 見本 122（円だけで作る動物のマーク） | |
|---|---|
| 大きさ | **80,956 バイト** |
| 円 | **12 個** |
| **閉じた辺の通り道** | **2,516 点** |

**80 KB の正本のうち、人が意味を読めるのは 59 行だけ。**残りは輪郭を解いた結果である。

一方、見本 127（ロゴのコンストラクション図。**円 10 個ほど**）は **約 7 KB** で、
**人が読める。**

> **コンパスで作れる図は、正本も小さい。**

## 2. **ソルバを作らない** —— ここがこの骨格の全部

PdM #6 の骨格案は `tangent-to`（接する）を中心に据えていた。
**接する円は一般に一意でない**ので、あれは拘束（constraint）であり、解くには

- 順序の決定
- 過剰拘束・不足拘束の判定
- 解が複数あるときの選択
- 収束しないときの扱い

が要る。**それは CAD であって、この製品ではない。**

**コンパスの作図は、そうなっていない。**

> 円を描く。別の円を描く。**その 2 円の交点**を次の点にする。その点を中心に円を描く……

**各手順は、前の手順の結果だけから決まる。**だから

| | 拘束（constraint） | 作図（construction） |
|---|---|---|
| 解き方 | 連立を解く | **前から順に評価する** |
| 中心の語 | `tangent-to`（接する） | **`intersect`（交わる）** |
| 解が一意か | 一般に一意でない | **「どちらの交点か」を書けば一意** |
| 解けないとき | 過剰／不足拘束 | **起きない。**「2 円が離れていて交点が無い」だけ |

**表計算と同じ形である。**セルは前のセルを参照し、循環参照だけが禁じられる。

### この 1 点で、PdM #6 の判断 4 が消える

> **4 解けなかったときどうするか。**接するはずの円が接しない正本は書けてしまいます。

前向きの評価では、**「接するはず」を書く場所が無い。**
起きるのは「**交点が無い**」だけで、それは符号 1 つで足りる。

## 3. 語 —— 最小の一式

実物（murmuraura のロゴ。**直線 1 本を含まない**）を分解して出た。

### 3.1 定数（`let`）

```yaml
let:
  R: 100            # ふところの半径
  H: 200            # 字の高さ
  phi: golden       # 語で書ける定数
```

- **ここだけが与えられたもの。**残りは全部ここから出る
- 語で書ける定数: `golden`（φ）/ `sqrt2` / `sqrt3` / `pi`。
  **`1.6180339887` と書かせない** —— φ は**作図で出る値**であって、十進数の近似ではない

### 3.2 長さ（`lengths`）

```yaml
lengths:
  stem:     R * phi^6      # 縦棒の半径
  shoulder: R / phi        # 肩
  weight:   H / phi^5      # 線の太さ
  gap:      H / phi^3      # 字間
```

- 式で書く。**前の行だけを参照できる**（循環参照を作れない）
- 使えるのは `+ - * / ^` と括弧、それに `distance(P, Q)`（2 点の距離）

### 3.3 点・円・線・弧

| 語 | 何を書くか |
|---|---|
| `points` | 与える点（**ここだけ座標を書く**）か、**交点** |
| `circles` | 中心と半径 |
| `lines` | 2 点を通る直線（または `y: <長さ>` の水平線） |
| `arcs` | 円の一部。**2 点のあいだ**か、角のあいだ |

```yaml
points:
  - id: A
    at: { x: 0, y: 0 }                 # 与える点
  - id: M
    intersect: [cA, cB]                # **2 円の交点**
    take: upper                        # 交点は 2 つある。どちらを採るか
circles:
  - id: cA
    center: A
    r: distance(A, B)                  # 半径は「2 点の距離」でもよい
arcs:
  - of: cStem
    from: P1
    to: P2
    weight: weight
    cap: round
```

`take` の語 —— `upper` / `lower` / `left` / `right` / `first` / `second`。
**書かなければ断る**（どちらとも決められないため）。

### 3.4 まだ入れない語

| | なぜ |
|---|---|
| `tangent-to`（接する） | **一意でない。**入れた瞬間ソルバが要る（§2） |
| `concentric`（同心） | `center` に同じ点を書けば済む。**語を増やす理由が無い** |
| `perpendicular`（垂直） | **作図で出る**（2 円の交点から）。見本 127 の手順 2〜3 がそれ |
| `parallel`（平行） | 同上 |

**足すのは、作図で出せないものが出てきたときだけ。**

## 4. `pins` の扱い —— **黙って無視しない。断る**

### 決まったこと（PdM #6。オーナー判断）

> D5 の芯は「**人が直したところが AI の再生成で壊れない**」ことであって、
> 「位置を pin できる」ではない。
> `construction` で人が直すのは `R` や φ の段であって、箱の座標ではない。
> **pin する対象が座標から定数へ移るだけで、芯は保たれる。**

したがって —— **この種類では `pins` が「与えた点」と「定数」に効く。**

```yaml
pins:
  R:
    value: 120        # 人が基準を変えた。**次の生成で壊れない**
```

### 条件 —— **`pins.position` を黙殺しない**

**上書きでも、黙殺でもなく、断ること。**

> **黙って消えるのが唯一の本当の事故です。**人が箱を動かして、次の生成で何も言わずに戻る ——
> これは利用者から見ると **D5 が壊れたのと区別がつかない。**

検証器に符号を置く（`pin-position-in-construction` のような形）。文言はこの向きで書く。

> この図では位置を直せません。位置は手順が決めています。直すのは `R` です。

**警告ではなく、明示の断り。**何を代わりに直せばよいかまで言う。

## 5. 「9 割」の測り方 —— **種類ごとに分け、横に並べない**

`docs/specs/003-9割の定義.md` は「人が触った要素 ÷ 全要素」で測っている。
**`construction` はそもそも座標を持たない**ので、
「置き場所を人が決めた割合」という問いが**成立しない。**

| 図の種類 | 何を「人の手直し」と数えるか |
|---|---|
| `structure` | `pins` の位置・大きさ・通り道（いまと同じ） |
| `placement` | 同上 |
| **`construction`** | **人が pin した定数の数 ÷ 定数の総数** |

- **問いを変えるのが正しい。**「人が定数をいくつ触ったか」なら、
  同じ向き（少ないほど AI が自力）で測れる
- **横に並べない。**`zumen_inspect` が返す `kind` で読み分ける
- **過去の数字と地続きにする。**`structure` / `placement` の数え方は 1 つも変えない

## 6. 描くときに要る、作図でないもの

作図だけでは絵にならない。**線の太さと端の形**が要る。

| | |
|---|---|
| `weight` | 線の太さ（長さの式で書ける） |
| `cap` | 端の形。`round` / `butt` |
| `terminal` | 端の玉（半径を長さの式で書く） |
| `trace` | **使った円の軌道を残すか。**作図図では残す（消すと、どう作ったかが読めない） |

**`trace` は既定で真にしない。**ロゴそのものを出すときは跡が邪魔になる。

## 7. 実物で確かめる —— **答えが分かっている**

PdM #6 が出した murmuraura のロゴは、**φ・H=200・R=100 の 3 定数**から
126 行のスクリプトで出ている。**確定値と SVG が既にある。**

だから `construction` が書けたら、**同じ絵が出るかで正誤が判定できる。**

こちらで逆再現したときの確定値（**10 / 10 一致**）。

| もの | 値 | 式 |
|---|---|---|
| 棒の半径 | 1794.427 | `R·φ⁶` |
| ふところ | 100 | `R` |
| 肩 | 61.803 | `R/φ` |
| 線の太さ | 18.034 | `H/φ⁵` |
| 字間 | 47.214 | `H/φ³` |
| 行間 | 76.393 | `H/φ²` |
| 色相の刻み | 137.508 | `360/φ²` |
| 横組 高さ | 218.034 | `H + H/φ⁵` |
| 横組 幅 | 2527.308 | 送り幅の和 ＋ 9×字間 |
| アイコン 一辺 | 1105.715 | 最長行の幅 ＋ 行間 2 つぶん |

**送り幅には φ の閉じた式が無い。**外接には 2 つの非 φ 成分が乗る ——
**線の太さの半分**と、**縦棒の円弧のふくらみ（サジッタ）**。

```
s(h) = SR − √(SR² − h²)        SR = R·φ⁶
s(100)     = 2.789             u / a の棒
s(138.197) = 5.329             m / r の棒
```

**ふくらみは棒の本数だけ乗る。**`a` は左が真円なので 1 つ、`u` は棒が 2 本なので 2 つ。
**これが `u` と `a` が同じ値にならない理由。**
