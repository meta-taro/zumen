# CLI / MCP の口と、姉妹プロジェクトとの境界（Issue 008）

- 実装（CLI）: `src/cli.ts`
- **MCP はまだ実装していない。ここで決めたのは範囲。**

---

## 1. 原則 — 単体で完結する

連携は前提であって後付けの機能ではない。だが**姉妹プロジェクトの機能として作らない。**

**zumen は単体で使えて、何も欠けない。**
md-business から呼ぶときも、呼ぶ側が zumen の CLI を叩くだけで済む形にする。

**姉妹側に依存している箇所は 0。** `src/` のどこからも md-business を参照していない
（テストの `experiments/s3/fixtures/md-business-packages.zumen.yaml` は、
向こうの `package.json` を**読んで起こした図**であって、依存ではない）。

## 2. CLI の口

すべて `node src/cli.ts <命令>`。`pnpm <命令>` でも同じ。

| 命令 | することは | 終了コード |
|---|---|---|
| `validate <図> ...` | 形式に適合しているかを見る | 読めない図があれば 1。**警告だけなら 0** |
| `measure <図> ...` | 「9 割」を測る（D3） | **不合格でも 0。** 検査ではなく物差し |
| `svg <図> [先]` | SVG を書き出す | 読めなければ 1 |
| `mermaid <図> [先]` | Mermaid を書き出す（翌日**読める**） | 読めなければ 1 |
| `drawio <図> [先]` | draw.io XML を書き出す（翌日**編集できる**） | 読めなければ 1 |
| `embed <Markdown> [先]` | 囲みを図へ差し替える（D4） | 読めなければ 1。**囲みが無ければ書き出さない** |
| `merge <正本> <提案>` | AI の提案を正本へ入れる（D5） | **競合が残っても 0** |
| `merge-driver <base> <ours> <theirs>` | Git のマージドライバ（D10） | 解けなければ 1（Git への合図） |

### 終了コードの考え方

**1 を返すのは「読めない」ときだけ。**

`measure` の不合格や `merge` の競合で 1 を返すと、
**CI を通すために指標を歪めたり、競合を黙って潰したりする動機が生まれる。**
どちらも、この製品が守ろうとしているものを壊す。

### CLI に置かないもの

- **競合の決着（`resolve`）。** そこが承認そのもので、**画面と人の仕事**（D11）。
  コマンドで一括処理できる形にすると、承認が「通す作業」になる
- `pins` を直接書く口。**`pins` に書いてよいのは人だけ**（仕様 §3.4 の規則 1）

## 3. MCP で開ける範囲

**AI エージェントに開けるのは、読みと提案まで。**

| 開ける | 名前（予定） | 中身 |
|---|---|---|
| ○ | `zumen_read` | 正本を読む |
| ○ | `zumen_validate` | 形式を検査する |
| ○ | `zumen_measure` | 「9 割」を測る |
| ○ | `zumen_to_mermaid` / `zumen_to_svg` | 書き出す |
| ○ | **`zumen_propose`** | 提案を正本へ入れた結果と、**競合の一覧**を返す |
| ✗ | 正本への直接の書き込み | **開けない** |
| ✗ | `pins` の書き換え | **開けない** |
| ✗ | 競合の決着 | **開けない** |

### なぜこの線か

**D5 の向きを、道具の形で守るため。**

AI が返すのは提案であり、正本ではない。
MCP から正本を直接書ける口を開けると、**その口を通って D5 が崩れる。**
規約で「書かないこと」にしても、**書ける口があれば、いつか書かれる。**

`zumen_propose` が書き込みを伴う場合も、通るのは `merge()` の 1 本だけにする。
`merge()` は構造上、

- **提案から `pins` を読まない**（AI が書いてきても採らない）
- **競合は適用せずに返す**

ので、**この口を通る限り人の指定は壊れない。**

### 人が承認する経路を潰さない

競合の決着を MCP に開けないのが、この Issue の注意そのもの。
**そこを開けた瞬間、AI が自分の提案を自分で承認できてしまう。**

## 4. ファイルの置き場所の作法

| もの | 置き場所 | なぜ |
|---|---|---|
| 図の正本 | 文書の隣。`<名前>.zumen.yaml` | **文書と一緒に版が動く**。別のディレクトリへ隔離すると、文書だけが更新されて図が取り残される |
| Markdown 内の図 | ```` ```zumen ```` の囲み（D4） | 着地点は md-business の本文。**別ファイルにすると本文と離れる** |
| 書き出したもの | 正本の隣。拡張子だけ違う | 対応が目で分かる |
| アイコンのパック | `.zumen/icons/<パック名>/`（D7） | **同梱しない**ものの置き場所。`.gitignore` 前提で案内する |

**`*.zumen.yaml` という名前が、`.gitattributes` のマージドライバ（D10）の対象そのもの。**
別の名前で置くと、構造マージが効かない。

## 5. 単体で使うときに欠けるもの — 無い

| 機能 | 単体で使えるか |
|---|---|
| 図を書く・読む・検査する | ○ |
| 自動配置・SVG | ○ |
| Mermaid / draw.io 書き出し | ○ |
| Markdown への埋め込み | ○（`pnpm embed`。md-business が無くても動く） |
| 提案の取り込みと競合の検出 | ○ |
| Git のマージドライバ | ○ |
| 「9 割」の計測 | ○ |

**姉妹側が要るのは、md-business の文書の中で図を出したいときだけ**（Issue 012）。

  なぜ `merge()` を通せないのかを先に書く。**便利だから、で開けない**

- 姉妹側への依存が 1 つでも入ったとき。**単体で完結する**という前提が崩れる
