# 承認のための最小 GUI — v0 の操作範囲（Issue 005）

- 対象: 作る順 B3
- **見た目の完成度は完了条件に含めない。汚くてよい**（PRD §3）
- 決めたのは**操作の範囲**だけ。色・字・配置は `DESIGN.md`（**人が書く**）

---

## 0. ここが最大の失敗経路

原案 §7 の v0 必須操作（選択・ドラッグ・リサイズ・接続・テキスト編集・削除・Undo・
Zoom / Pan・保存）は、**既存の作図ソフトの機能一覧と区別がつかない。**

これを揃えることを目標にすると、機能の少ない作図ソフトが出来上がり、
draw.io を部品にしなかった判断（D1）を自分で裏切る。

**GUI に要るのは編集機能そのものではなく、AI の書き換えを人が承認できること。**

---

## 1. 承認に要る 3 つ（ここから逆算する）

| | 要ること |
|---|---|
| A | **AI が何を書き換えたのかが見える** |
| B | **人が動かしたものを AI が戻していないかが見える** |
| C | 戻されていたら、**そこだけ人の指定として固定できる** |

以下の操作は、すべてこの 3 つのどれかに紐づく。
**紐づかない操作は v0 に入れない。**

---

## 2. v0 で作る操作

| # | 操作 | どれに要るか | なぜ要るか |
|---|---|---|---|
| 1 | 図を開く／保存する | A B C | 正本はファイル。開けなければ何も始まらない |
| 2 | 図を見る（描画・Zoom・Pan） | A B | 画面に入らない図は、差分も競合も見えない。**編集ではなく閲覧** |
| 3 | **要素を 1 つ選ぶ** | B C | 「どれの話をしているか」を人と機械で一致させる。複数選択は要らない |
| 4 | **要素をドラッグして位置を決める** | B | **人の手直しの最小形**。これが無いと「戻されたか」を試せない。結果は `pins.position` に入る |
| 5 | 文章で指示を出し、提案を受け取る | A | AI の書き換えはここから来る |
| 6 | **適用前に差分を見る** | A | 適用してから見るのでは、承認ではなく事後報告になる |
| 7 | **競合の一覧を見て、片方を選ぶ** | B C | 中心。`merge()` が返した競合を出し、`resolve()` に渡す |
| 8 | 人の指定が効いている要素に印が出る | B | 印が無いと、**自動配置なのか自分が置いたのかが区別できない** |

**8 個。これ以上は v0 に入れない。**

### 4 と 8 について

ドラッグは「作図」のためではなく、**保持を試すため**にある。
人が 1 つ動かし、もう一度 AI に頼み、**戻っていないことを目で確かめる** — この 1 往復が
この製品の全部であり（S1）、そこに要る最小の操作が 4 と 8。

---

## 3. v0 で**作らない**操作

| 作らないもの | 代わりに何で足りるか |
|---|---|
| **リサイズ** | 承認に要らない。大きさは自動でよい |
| **接続の作成・削除** | 構造は AI が書く。人はテキストで直す |
| **ラベルの画面上での編集** | 正本のテキストを直す。**GUI を万能にしない** |
| **要素の削除・追加** | 同上。構造は文章で頼む |
| ~~Undo / Redo~~ | **2026-09-07 に方針を変えた（D19）。** 自動保存を入れると「保存しない」という逃げ道が消えるので、取り消しと対で要る。**積むのは正本のテキストそのもの**なので二重管理にならない。持続はせず、残る記録は Git のまま |
| **複数選択・整列・グループ操作** | 承認のどれにも紐づかない |
| **テンプレート・図形パレット** | 図形の量は勝負どころではない（D7 でアイコンを同梱しないと決めた） |
| **共同編集・Web 版** | PRD §4 |
| **見た目の設定（テーマ・フォント）** | v0 では固定。`DESIGN.md` が決まってから |

---

## 4. 止めるべき条件（自分で気づくための線）

次のどれかが起きたら、**GUI の作り込みを止めて Issue 003（9 割の定義）へ戻る。**

- v0 の 8 個の外にある操作を「使いにくいから」という理由で足そうとしている
- 承認の 3 つ（A B C）に紐づかない画面を作っている
- **見た目の調整に時間を使っている。** 汚くてよい、が守れていない

**機能を足したくなったら、Issue 003 の指標が改善するかで判断する。
改善しない機能は、この製品の機能ではない。**

## 5. 人に決めてもらうこと（AI は埋めない）

- **`DESIGN.md`（色・タイポグラフィ・レイアウト）は空のまま。**
  ベースルール §11 により、AI は埋めない
- 姉妹アプリ `md-business/apps/desktop/DESIGN.md` に、**同じ人が書いたデザイン正本**がある
  （Linear 風・CSS custom properties でトークン化・ライト主軸＋ダーク同等）。
  D1 の「既存シリーズに揃える」を踏まえるなら、**そこへ揃えるのが自然**だが、
  **揃えるかどうかは人が決めること**
- v0 の実装では、**色や寸法を 1 か所のトークンに集める**。
  `DESIGN.md` が決まったとき、そこだけ差し替えれば済む形にしておく
  （文言を `src/messages.ts` に集めたのと同じ理由。D9）
